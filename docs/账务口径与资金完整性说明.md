# KXT 财务系统 · 账务口径与资金完整性说明

> 本文汇总现金流 / 资金池 / 排款付款全链路的**取值口径**与**资金完整性防线**，
> 作为财务复核与后续开发的单一权威参考。所有口径以「实际收付时间、现金收付制」为总纲。
> 若代码与本文冲突，以本文为口径基准并修正代码。

---

## 0. 总纲

1. **现金收付制**：现金流与资金池只认**真实的银行/现金收付事件**，按其**实际发生日**入账。
   计划日、到期日、预计日等一律**不参与**现金类数字。
2. **权责 ≠ 现金**：应收 `actual_receivable`、毛利（收入−成本）是权责/台账口径；
   现金流/资金池是现金口径。二者**不可混用、不可互相重复计**。
3. **核销是账务重分类，不是现金事件**：预收核销、预付核销都不产生新的现金进出。
4. **单一正源**：每个派生量都以一个明确的底表为唯一正源整体重算，杜绝增量漂移。

## 1. 现金流入构成（现金流分析 / 资金池）

| 来源 | 底表 / 字段 | 归期日 | 说明 |
|---|---|---|---|
| 应收回款 | `ARPayment.amount`（排除非现金来源） | `payment_date` | 冲减应收；只有真实收现计入 |
| 日常收款 | `DailyReceipt.amount` | `receipt_date` | 账外/补充现金流入，全额计入（见 §4） |
| 预收 | `AdvanceRecord(预收).advance_amount` | `occur_date` | 客户预付货款，收现即入 |

- **非现金来源**：`NON_CASH_PAYMENT_SOURCES = ('预收抵扣', '内部往来')`，从回款中排除——
  这些不是新的现金进账（预收在 `occur_date` 已计、内部往来非经营现金）。
- **未兑付承兑汇票**：不算「可动用货币资金」，**不进资金池余额**；但**计入**现金流分析的经营活动流入
  （二者刻意不同，见 §5）。

## 2. 现金流出构成

| 去向 | 底表 / 字段 | 归期日 | 说明 |
|---|---|---|---|
| 实付分期 | `PaymentInstallment.pay_amount`（排除软删排款） | `pay_date` | 排款的**真实付现** |
| 预付 | `AdvanceRecord(预付).advance_amount` | `occur_date` | 我方预付供应商，付现即出 |

- **现金流出 = 实付分期 + 预付**。**不含**预付核销冲抵（见 §3）。

## 3. 预收 / 预付 与核销的角色（关键）

**预收 / 预付本身**是真实现金事件，在 `occur_date` 计入流入 / 流出。

**预收核销 / 预付核销是非现金结转，一律不进现金流 / 资金池**：

- **预收核销**：把预收结转到某张应收上。系统生成一笔 `source='预收抵扣'` 的 `ARPayment`
  （`payment_date = writeoff_date`）冲减应收，但该来源是非现金、已被 §1 排除 → 不重复计。
- **预付核销**：把预付资产结转到某张应付（排款）上。
  - 实付分期 (`total_paid`) 与预付核销冲抵 (`prepaid_offset_amount`) 是计划的**两块互不重叠部分**：
    `covered = 已付 + 冲抵`。实付分期即「本期真实付现」。
  - 预付的现金早在 `occur_date` 作为「预付」流出；核销无新现金事件。
  - 因此**现金流出不从实付里扣冲抵**，资金池余额也**不加回冲抵**。

> 历史教训：曾错误地在现金流出/池余额里对冲抵做 `-(p - po)` / `paid - offset`，
> 等于把「预付时已流出、现已结转」的钱当现金又加回来，系统性**虚增资金池、低估流出**，
> 甚至把与核销同月的真实实付整笔抹掉。已全部修正为「核销不进现金」。

**校验不变量**：`已付 + 已冲抵 ≤ 有效计划`（有效计划 = 计划调整额优先，否则计划总额）。
录入实付分期、创建核销、以及**仅改计划/调整额（不带分期的编辑）**三条路径均须满足，防假结清。

## 4. 日常收款 与 预付退款闭环

- **日常收款**：与回款、预收并列的第三条**实际现金流入**台账，按 `receipt_date` 全额计入现金流+资金池。
  收款方式仅现金/微信/银行转账/自定义，**全是可动用现金**（无承兑，故无需像回款那样排除未兑付承兑）。
- **定位**：账外/补充收款。其中「项目收款」= **当月发生、当月收款、从未形成应收**的现金，
  因此**与应收回款业务互斥、天然不重复计**；日常收款不登记应收、不冲减应收 outstanding、不动预收/预付台账。
- **预付退款闭环（可选）**：来源=「预付退款」时可关联一笔预付。
  - 退款仍是现金流入（不变）；关联**额外**冲减该预付的**未核销余额**（`balance = 金额 − 累计核销 − 累计退款`）。
  - 纯预付资产台账的事，**不影响任何现金口径**；退款额 ≤ 未核销余额；增/改绑/删除后重算预付余额。

## 5. 资金池 vs 现金流分析（口径差异，刻意不同）

| 维度 | 资金池 | 现金流分析 |
|---|---|---|
| 含义 | 某时点**可动用货币资金余额** | 选定区间的**现金净流量** |
| 期初基准 | 含（`CashPoolConfig.initial_amount`） | 不含 |
| 池间调拨 | 计入（approved 生效） | 不计（内部划转非经营现金） |
| 未兑付承兑 | **排除**（贴现/到期前非货币资金） | **计入**（经营活动流入） |

> 因此「资金池余额」与「现金流分析净额」**不应直接相等**，单事业部尤其明显。

## 6. 前瞻口径（预判，非现金已发生）

- **刚性待付 committed** = `有效计划 − 已付 − 预付冲抵`，按 `planned_date` 分 30/60/90 天窗。
  这里减冲抵是**对的**——预付覆盖部分未来无需再付现。**与「实际现金」是两个维度，互不影响。**
- **预期流入 expected_in** = 未结清应收按 `due_date` 分窗；逾期单列。
- 预判/预测口径**不得**与「已发生现金」叠加重复计（同一笔不能既算已收又算将来会收）。

## 7. 排款 → 付款 全链路 · 资金完整性防线

**流程**：审批(ApprovalRecord) → 排款(Payment + 计划批次 PaymentPlanItem) → 付款(实付分期 PaymentInstallment)。

**单一正源**：审批「已排款」`scheduled_amount` = 该审批全部**在册**排款的计划批次之和
（`_reconcile_approval_schedule`，排除软删；每次批次变动后调用，幂等）。

**六道防线：**

1. **不可超额排款**：单审批多批 / 拆到多条排款，累计计划批次之和都被 bound 在审批申请金额内
   （追加批次、编辑批次、台账改总额、审批转排款各路径均在**审批行锁内**以批次之和实时复核）。
2. **不可超付**：`已付 + 已冲抵 ≤ 有效计划`；批量付款在**排款行锁内**以最新 `remaining` 复核（TOCTOU 防护）。
3. **不可假结清**：下调计划/调整额时按 `covered = 已付 + 冲抵` 校验，不得降到低于已覆盖额。
4. **删除/退回的现金保护**：
   - 关联**预付核销**的排款：一律**禁止**删除/退回，须先撤核销（防核销悬空、预付余额失真）。
   - 有**实付分期**的排款：默认拦截；**仅超级管理员**可强制退回/删除（策略 B），且为**软删可还原**——
     堵住「退回→审批已排款归零→重排→重付」的双付通道。
5. **释放对账**：删除/退回/还原/彻底删除均在同事务内调用 `_reconcile_approval_schedule`，
   软删排款的批次被排除 → 审批已排款如实归零、可重排；幂等无残留。
6. **并发防护**：
   - 去重键 = 部门+审批单号+收款方+计划日期+计划金额，DB 唯一约束兜底；
     空/占位(全0)单号补充按「部门+收款方+计划日+金额+同为空/占位单号」查重。
   - 首次排款在**审批行锁内重查在册付款**再决定新建/追加（防一审批并发建多条排款）。
   - **预付核销创建 ↔ 排款软删**：两侧都 `select_for_update` 锁定同一排款行并锁内复检，串行化
     （防核销落到刚软删排款上导致预付余额少一块）。

## 8. 通用工程口径

- **金额**：全部 `DecimalField(decimal_places=2)`；比较按 2 位量化，避免浮点误差把「实付==计划」误判。
- **聚合**：对可能产生 JOIN 行乘积的场景（多批次/多分期）用**关联子查询**而非 `Sum('a__b')`，
  兼容 MySQL（避免 HAVING 1054）且不重复计。
- **软删**：现金/已付/未收各报表一律 `deleted_at__isnull=True` 过滤；回收站可还原。
- **时间**：一律 `timezone.localdate()`，避免 UTC 偏移把跨零点的事件归错日。

## 9. 应收账款（AR）口径

- **未收余额（权责口径）**：`outstanding = (预估上账 estimated + 账实差额 account_diff_adjustment) − Σ全部回款`。
  - **用全部来源冲减**：回款、预收抵扣、内部往来、承兑汇票（无论是否兑付）都冲减 outstanding——
    会计上「应收未收」= 还欠多少，与是否为现金无关。**这与现金口径（§1 排除非现金来源）刻意不同、正交。**
  - **负未收被拦截**：`recompute_derived` 在 outstanding<0 时**抛错**（而非 `max(0)` 掩盖）+ DB `CheckConstraint ≥ 0`。
    多收须走「差额调整」或「预收」，不允许把回款录成负未收。
  - **编辑回款**同样受上限约束：新金额 ≤ 当前未收 + 本笔原额；且金额 UPDATE 与重算信号**同事务**，防坏账。
- **实际应收 actual_receivable** = 预估 + 账实差额；`invoice_mismatch` = 已开票且开票额 ≠ 实际应收（未开票不报警）。
- **到期日** `compute_record_due_date` = 对账周期结束日（按 `cycle_start_day` 锚点）+ 项目总账期天数；
  项目账期参数变更经信号重算名下应收，与 `save` 同源。
- **账龄/逾期**：逾期判定统一 `due_date < today`（严格），`timezone.localdate()`；分桶边界 `lt/gte` 无缝无叠。
- **软删除（回收站）**：应收记录删除进回收站可还原（默认管理器过滤，`all_objects` 供回收站）。
  守卫与付款侧同纪律：有「预收抵扣」回款一律拦（须先撤核销）；有真实回款仅超管可强制。
  软删记录的回款按 `ar_record__deleted_at__isnull=True` 从现金流/资金池/预算达成排除；
  还原时重算未收。彻底删除级联删回款（审计不可恢复），预收抵扣仍拦截。

## 10. 财务分析口径（现金 vs 权责，勿混用）

- **caiwu 分析域（驾驶舱/预测/指标/目标/业财融合）不产出现金净流量**——不引用 `cash_flow_window`。
  资金支出侧（排款计划/实付）与权责收入/毛利各自成文、不做算术相加，无「计划当现金」混用。
- **现金类图表**（如项目现金流 `analytics_project_cashflow` 的「流入」）须与 §1 一致，**排除非现金来源**。
- **应收回收率 vs 现金回款率**：以「冲减应收」为口径的回收率可含全部来源（含预收抵扣/内部往来）；
  以「现金」为口径的必须排除非现金来源。两者语义不同，命名与取数须各自自洽。
- **项目毛利**：收入(6001/6051)、成本(6401/6402)均取记账净额、**不含税、同确认时点**；多期/多批次导入
  **按 (事业部,年,月) 整体替换**（幂等，不重复计）。
  - **未挂项目池（「无」）**：`direct` 单列未分摊成本；`allocated` 把未挂**成本**按收入比例摊入各项目，
    但未挂**收入**两种模式都保留在合计（收入不参与分摊）——否则 allocated 总收入/毛利偏小且与对账口径背离。
- **目标分解**：月度合计 = 年度目标（同事务锁行校验，容差 1 元）；完成率/同环比分母为 0 均返回 None。

## 11. 全系统审查补充口径（审批 / 钉钉 / 发票 / 预收预付 / 预算报表 / 权限）

**审批台账（在途支出的正源）**
- 真实（非全0占位）21 位单号**全局唯一**：手工新建、Excel 导入、预检导入、钉钉同步四条入口
  统一防重（库内 + 同批文件内），杜绝在途支出双计与钉钉状态错配。
- **已有在册排款的审批被锁定**：不可下调金额至低于在册已排款、不可离开 approved 态
  （退回待审批/拒绝/撤销均须先退回排款批次）——人工编辑与钉钉三条回写链路
  （status-sync / refresh / 事件回调）同一道闸；已归档记录钉钉不覆盖金额与状态。
- 审批编辑全程在行锁内、显式 update_fields，防与并发排款对账互相覆盖。
- 回收站：付款还原前置两道检查——父审批仍在回收站不可单独还原；还原后累计排款
  将超申请金额（回收站期间已重排满）则拒绝。

**回款 / 开票（应收侧现金入口）**
- **回款日期不得晚于今天**（单笔、编辑、批次分摊三路径）——回款以实际收款日入账，
  未来日期会提前美化当期回款/现金流/账龄。
- 开票日期保留**首次开票日**（票后等待期以此推算，二次开票不覆写）。
- 撤销开票事件在事件行锁内执行（防并发双重回退）；批次成员已有开票/批次回款事件时
  不可改挂/脱离批次（防事件孤儿化、撤销永久失效）。
- 客户维度「已回款」= Σ(实际应收 − 未收)，与应收台账单源一致（不得用 开票 − 未收）。

**预收预付台账**
- 改动余额的全部路径（核销创建/编辑、预付退款创建/编辑）在**预收预付行锁**内校验与写入，
  与并发核销/退款串行——无锁校验会让两笔各自通过后合计超额（DB 非负约束只查单行写入值，
  拦不住聚合超额）。
- 有核销或退款关联的记录：不可删除、不可翻转方向（须先撤核销/解绑退款）。
- 导入按业务键（方向+部门+往来单位+发生年月+金额+日期）防重，重复行跳过。
- 批量核销：散单预收（未挂项目）往来单位为空时拒绝冲抵（空值会让客户匹配短路）。

**预算 / 周期报表**
- 预算「实际回款」排除非现金来源，与周期报表同口径（同一达成率两页一个数）。
- 周期报表现金流段委托 `cash_flow_window` 统一口径（本期 + 本年累计）。

**权限**
- 子资源端点（催收日志等旧兼容垫片）与主资源同规格：部门作用域 + 页面权限 + 写权限
  三道闸缺一不可。

## 12. 变更简史（历轮账务口径修正）

| 主题 | 修正 |
|---|---|
| 预付核销时间口径 | 现金流/资金池统一按 `AdvanceWriteoff.writeoff_date`（曾误用 planned_date） |
| 预付核销是否进现金 | **不进**——移除现金流出/池余额里的冲抵扣减（曾虚增池、低估流出） |
| 日常收款 | 确认为纯现金流入；项目收款=当月即收、非应收，天然不重复计 |
| 预付退款闭环 | 可选关联预付并回冲未核销余额，不影响现金口径 |
| 计划下调校验 | 不带分期的编辑也按 `covered=已付+冲抵` 校验，堵假结清 |
| 已付排款强退 | 仅超管可强制（策略 B），堵双付通道 |
| 空/占位单号 | 补充维度查重 |
| 并发 | 首次排款锁内重查；核销↔软删跨行锁 |
